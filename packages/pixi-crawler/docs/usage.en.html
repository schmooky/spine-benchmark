pixi-crawler - a performance profiler for Pixi 8

An embeddable measurement instrument: a per-frame breakdown of where the milliseconds go (CPU pre-work, pixi build / transform / execute, Spine, true GPU time), workload counters, a HUD, and telemetry. Drop it into any app in one call.

Install

pixi.js is a peer dependency. It is critical that your app's pixi version and the package's match exactly: the crawler patches pixi prototypes, and a version mismatch means it patches the wrong graph. 

npm install @spine-benchmark/pixi-crawler

Quick start

One call: mountCrawler(app). Shows the HUD by default and auto-disposes itself on pagehide. 

import { Application } from "pixi.js";
import { mountCrawler } from "@spine-benchmark/pixi-crawler";

const app = new Application();
await app.init({ background: "#101317", resizeTo: window });

// HUD visible, auto-dispose on pagehide
const crawler = mountCrawler(app);

// headless (no HUD) + telemetry
const headless = mountCrawler(app, { hud: false, telemetry: { sink } });

mountCrawler accepts a Pixi Application, or any object with { renderer, ticker } fields; the second argument is a config object (see below) plus an autoDispose flag (default true).

Full control

For full lifecycle control, construct it directly and manage attach / detach / dispose yourself. 

import { Crawler } from "@spine-benchmark/pixi-crawler";

const crawler = new Crawler({
  targetFrameMs: 1000 / 60,   // frame budget the HUD normalizes bars against
  hud: !import.meta.env.PROD,
  spineProfile: { enabled: true },
  telemetry: { sink, sampling: { windowMs: 5000 }, rawFrames: "on-overrun" },
});

crawler.attach(app.renderer, app.ticker);

window.addEventListener("pagehide", () => void crawler.dispose());

Contracts & constraints

The app's ticker must NOT be Ticker.shared. The app must own its own ticker: under the shared ticker Spine collides with the crawler. This is the one hard incompatibility.
  • Pixi versions must match exactly - the crawler patches pixi prototypes; a version mismatch means it patches the wrong graph.
  • gpuMs is null on Safari / iOS - no EXT_disjoint_timer_query_webgl2 extension there. CPU measurements still work; the crawler discards "disjoint" (unreliable) GPU-timer readings itself.
  • dispose() / detach() restore every patched method (including TextureSource.prototype.unload). Call one of them on unmount.
  • Every measurement axis has overhead. Only enable what you actually read (see Configuration).

Manual render loop

If your app drives its own render (ticker stopped, your own requestAnimationFrame), bracket each frame manually. Under a running ticker these calls are not needed - attach() already wires the frame boundaries to the ticker. Mixing the two modes double-counts. 

app.ticker.stop();

function frame() {
  crawler.frameStart();
  // ...advance the scene, then render...
  app.render();
  crawler.frameEnd();       // flushes one FrameRecord
  requestAnimationFrame(frame);
}
requestAnimationFrame(frame);

Configuration

Every CrawlerConfig field is optional; each gates one subsystem.

FieldDefaultWhat it does
hudoffShow the DOM HUD overlay. On via mountCrawler.
targetFrameMs1000/60Frame budget in ms: the HUD normalizes bars and colors status against it.
bufferSize600Frame ring-buffer size (how many recent FrameRecords to keep).
enableGpuTimingonTrue per-frame GPU time via EXT_disjoint_timer_query (gpuMs).
deepRenderSplitonCPU render-time split by phase (build / transform / execute / ...).
filterProfileonFilter timing (push / apply / pop) and pass count.
textureTrackingonTexture uploads / unloads, bytes, active GPU count.
spineProfileoffPer-phase Spine breakdown. Patches Spine's methods - do not enable if you separately time inside spine.update().
pipeProfileoffPer-render-pipe-call timing. The heaviest overhead of any flag.
workloadCostonOpen device-independent workload measure (derived, read on demand).
gpuCostonOpen GPU-heaviness measure (fill footprint + filters).
hudTheme"slate"HUD color preset: "slate" (default), "warm", or "contrast". Sets --sbc-* CSS variables only - no measurement effect.
hudMotiononSmooth expand/collapse micro-interaction on the HUD. Purely cosmetic; set false for an instant, transition-free HUD.
selfProfileoffPer-function self-time via the W3C JS Self-Profiling API (needs a Document-Policy: js-profiling header, Chromium only).
memoryProfileoffProcess memory via measureUserAgentSpecificMemory() (needs cross-origin isolation).
telemetryoffPeriodic aggregate flush to your sink (see below).

Reading measurements

The crawler does not require the HUD - read frames directly and build your own panel.

const f = crawler.getLastFrame();     // the latest FrameRecord (or undefined)
f.gpuMs;                              // true GPU time, ms (null without a timer)
f.counters.drawCalls;                // draw calls
f.counters.verticesDrawn;            // vertices/indices
f.counters.stencilMaskPasses;        // stencil masks
f.counters.renderTargetSwitches;     // render-target switches
f.renderSplit?.updateRenderablesMs;  // CPU render phase, ms

crawler.getFrames();               // the whole ring buffer
crawler.getWorkloadCost();        // open workload measure + bottleneck
crawler.getGpuCost();             // open GPU-heaviness measure
crawler.getWorstFrame();          // worst frame + a scene dump

// GPU queries land 1-3 frames late; drain them at the end of a measurement window:
await crawler.flushPendingGpu();

Telemetry

Set telemetry.sink and the crawler sends aggregated batches (windowed percentiles). Fire-and-forget: the crawler does not wait for a response and catches + logs errors. The transport is yours. 

const sink = {
  send(batch) {
    navigator.sendBeacon("/telemetry", JSON.stringify(batch));
  },
};

const crawler = new Crawler({
  telemetry: {
    sink,
    sampling: { windowMs: 5000 },   // flush cadence, ms
    rawFrames: "on-overrun",        // raw frames only on overruns
  },
});
crawler.attach(app.renderer, app.ticker);

// tag the current scene for calibration-corpus attribution
crawler.setTelemetryLabel("bonus-game");

HUD, themes & motion

The HUD is a muted, neutral panel over the scene (no neon). Click "-" to collapse it to an fps badge; the header carries a small frame-time sparkline so a steady vs. jittery line reads at a glance. The whole palette is driven by --sbc-* CSS variables on the root #sbc-crawler - override a handful of them for your own theme, or pick one of the three built-in presets via config.hudTheme. 

import { mountCrawler } from "@spine-benchmark/pixi-crawler";

mountCrawler(app, { hudTheme: "warm" });

/* or override tokens yourself, in your own CSS: */
/* #sbc-crawler.sbc-hud { --sbc-bg: rgba(22,19,17,.95); --sbc-accent: #c2a878; } */

Expand/collapse plays a brief settle animation by default (hudMotion: true); set it false for an instant, transition-free HUD.

Recording a session

Frames can be recorded and saved to JSON, to replay later in the inspector (record/save/load buttons are also in the HUD). 

crawler.startRecording();
// ...reproduce the problem scenario...
crawler.stopRecording();
const recording = crawler.getRecording();   // { version, frames, ... } -> serialize to JSON
